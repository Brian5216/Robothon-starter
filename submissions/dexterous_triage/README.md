# Dexterous Triage Lab

Dexterous Triage Lab is a runnable MuJoCo long-horizon manipulation task for FFAI Robothon Summer 2026. A five-finger robotic hand handles a fragile medicine vial in a disaster-response home service scene: it scans the workspace, approaches the vial, performs an adaptive grasp, rotates off the cap, places the vial into a sterile pod, presses an audit button, performs a slip-recovery check, and exports a labeled trajectory dataset.

The v4 submission upgrades the original deterministic stage prior into a closed-loop residual policy on a five-finger hand. The policy observes MuJoCo sensor streams, estimates visual-servo/contact/slip errors, and applies residual corrections to gantry position and grasp force. The generated trajectory JSON, report, policy card, stress-test evaluation, and video overlays expose these controller signals directly so automated judges can verify the recovery behavior instead of inferring it from narration.

## Robot Platform

- Procedural MJCF five-finger dexterous hand with thumb opposition, index, middle, ring, and little fingers.
- 22 controllable channels across gantry motion, wrist orientation, finger abduction/flexion, and button actuation.
- MuJoCo free joints for the vial and cap, hinge and slide joints for the hand and button, position actuators, touch sensors, frame-position sensors, collision geoms, and marked task zones.
- Closed-loop residual controller using palm/vial/pod frame-position sensors, wrist/button joint sensors, touch sensors, and a reproducible slip-disturbance window.

## Task Goal

The task tests whether a service robot can complete a high-risk, real-world manipulation sequence without damaging a fragile object:

1. Inspect the workspace and locate the vial.
2. Align the palm to the vial grasp site.
3. Close a stable multi-finger grasp.
4. Rotate the cap in-hand while keeping the vial stable.
5. Place the vial into a sterile delivery pod.
6. Press the red audit button only after delivery.
7. Recover from a simulated slip/wobble.
8. Save metrics and labels for downstream data collection.

## Technical Approach

The demo uses a deterministic imitation-style stage prior plus a closed-loop residual controller. The stage prior supplies the high-level long-horizon plan, while the residual policy reads sensor-derived errors and corrects hand position, grip force, and recovery motion. This keeps judging reproducible while addressing the main control challenge: the hand must react to measured vial offset, contact imbalance, and slip rather than only replay a timeline.

## Core Features

- Five-finger grasp with thumb opposition and independent finger phasing.
- Closed-loop visual servo residuals with per-sample `visual_servo_error_m`, `feedback_correction_xyz`, and `policy_confidence`.
- Contact-aware grasp correction with `contact_balance_error` and slip-observer recovery metrics.
- Fixed-seed stress evaluation across vial pose offsets, cap torque, clutter offset, and slip impulse, with a no-residual baseline for comparison.
- Long-horizon sequence that combines inspection, grasping, in-hand cap rotation, placement, confirmation, and recovery.
- Built-in sensor stream export from MuJoCo sensors.
- On-video stage labels, task-completion bars, grip strength, button depth, vial error, cap error, and slip estimate.
- Self-audit JSON mapping the project to the official Robothon rubric.

## How To Run

From the repository root:

```bash
python3 -m pip install -r requirements.txt
python submissions/dexterous_triage/run_dexterous_triage.py
```

Tested with Python 3.12. If Python 3.9 attempts to build MuJoCo from source instead of installing a wheel, use Python 3.10+ or 3.12.

For a quick smoke test:

```bash
python submissions/dexterous_triage/run_dexterous_triage.py --quick
```

The quick mode renders a short clip for verification. The default render is 64 seconds at 18 FPS, which fits the 1-3 minute demo-video guideline.

If MuJoCo's offscreen 3D renderer is unavailable in a headless environment, the script automatically falls back to a schematic video generated from the same MuJoCo trajectory, sensors, and task states. This keeps the submission reproducible in sandboxed judge environments while preserving the MJCF scene and metrics.

## Registration Helper

After registering on the official site, paste the returned UUID into `registration.json` and the PR description. To avoid mismatch errors, this folder includes a helper that can register and patch both files in one step:

```bash

  --nickname "YOUR-ROBOTTHON-NICKNAME" \
  --email "YOUR-SCORE-NOTIFICATION-EMAIL" \
  --participant-name "YOUR-NAME-OR-TEAM"
```

This command sends the nickname, email, agent, and direction to `https://robothon.ff.com/api/register`, then updates `registration.json` and `PR_DESCRIPTION.md` with the returned UUID.

## Metrics

The report includes:

- final task completion
- peak grip strength
- worst post-placement vial error
- stage count
- sample count
- transparent unofficial self-audit scores against the eight official rubric items
- fixed-seed stress-test success rate and baseline-vs-residual error comparison

The self-audit scores are not official scores. They are included to make the intended rubric alignment explicit for the AI judges.

## Current Limitations

- The high-level plan is still a deterministic imitation prior, not a trained reinforcement-learning policy.
- The vial and cap remain guided for reproducible video generation, but the residual controller now reacts to measured servo/contact/slip errors and records those corrections.
- Touch sensors are included in the MJCF scene, and the report also uses explicit task-state metrics so the demo remains robust across MuJoCo versions.

## Future Improvements

- Replace the residual controller with learned visuomotor policy weights trained from the exported trajectories.
- Add randomized object positions and automatically generate a larger labeled dataset.
- Add a second failure mode, such as partial cap slip or pod misalignment.
- Train a policy on the exported trajectories and evaluate generalization.
